# Revenue Estimation Engine

## Назначение

Revenue Estimation Engine формирует объяснимый `RevenueImpact` для `BusinessOpportunity`.

В RC2.4 это не механизм прогнозирования выручки. Он извлекает только уже указанный в `evidence` денежный диапазон и никогда не вычисляет сумму по косвенным признакам.

## Архитектура

```text
BusinessOpportunity + RevenueIntelligenceContext
                    │
                    ▼
       RuleBasedRevenueEstimator
                    │
                    ├── поиск первого явного денежного диапазона в evidence
                    ├── разбор чисел и валюты
                    ├── проверка порядка границ
                    ├── качественная оценка confidence
                    └── объяснение метода и допущений
                    │
                    ▼
              RevenueImpact
```

Компонент расположен в:

- реализация: `backend/src/travel_revenue_ai/revenue_intelligence/revenue_estimator.py`;
- доменные модели: `backend/src/travel_revenue_ai/revenue_intelligence/models.py`;
- контекст: `backend/src/travel_revenue_ai/revenue_intelligence/contracts.py`.

`RuleBasedRevenueEstimator` не зависит от ORM, CRM, базы данных, LLM, внешних API и Pipeline. `RevenueIntelligenceContext` принимается как часть стабильного интерфейса, но в текущих правилах не используется для вычисления денег.

`NullRevenueEstimator` — безопасная реализация по умолчанию. Она всегда возвращает `None` и не создаёт оценку.

## Алгоритм

1. Оценщик просматривает `opportunity.evidence` в исходном порядке.
2. Он выбирает первый текст, содержащий полный явный диапазон в одной валюте.
3. Поддерживаемые разделители границ: `до`, `-`, `–`, `—`.
4. Суммы разбираются без округления; поддерживаются пробелы, неразрывные пробелы, точки и запятые в дробной части.
5. Валютный маркер нормализуется к трёхбуквенному коду.
6. Если нижняя граница больше верхней, диапазон не исправляется: результат остаётся без сумм.
7. Если валидного диапазона нет, создаётся `RevenueImpact` со значениями `amount_min=None`, `amount_max=None`, `confidence=low` и методом `unknown_insufficient_explicit_evidence`.
8. Для валидного диапазона используются:
   - `calculation_method=rule_based_explicit_evidence_range`;
   - исходные границы из `evidence`;
   - explanation и assumptions для аудита решения.

## Confidence

Уровень confidence не является прогнозом и не изменяет денежный диапазон.

| Условия возможности | Итоговый confidence |
| --- | --- |
| Исходный `high`, срочность `high` или `critical`, есть распознанные сущности | `high` |
| Исходный `medium` или `high`, но условий для `high` недостаточно | `medium` |
| Все остальные случаи | `low` |

Тип возможности, срочность, сущности и исходный confidence не используются для расчёта суммы. Они только отражаются в assumptions и участвуют в качественном confidence.

## Supported scenarios

### Поддерживаемые типы возможностей

Оценщик работает одинаково для всех типов `OpportunityType`:

- `revenue_growth`;
- `cost_saving`;
- `retention`;
- `pricing`;
- `segment`;
- `operational`.

Тип не создаёт и не меняет сумму: оценка возможна только при явном диапазоне в `evidence`.

### Поддерживаемые форматы

Примеры корректных диапазонов:

```text
от 10 000 до 25 000 ₽
1 500–2 750 RUB
1250.5-2500.75 USD
15,5 до 20,75 €
5 000—7 000 рублей
```

Поддерживаемые валюты:

| Маркеры | Нормализованный код |
| --- | --- |
| `₽`, `руб`, `руб.`, `рублей`, `RUB`, `RUR` | `RUB` |
| `$`, `USD` | `USD` |
| `€`, `EUR` | `EUR` |

## Ограничения и гарантии

### Гарантии

- Результат детерминирован: одинаковые входы дают одинаковый `RevenueImpact`.
- Входные `BusinessOpportunity` и `RevenueIntelligenceContext` не изменяются.
- Диапазоны из разных evidence не агрегируются.
- При нескольких валидных диапазонах берётся первый по порядку.
- Обратный диапазон не исправляется автоматически.
- Без явного диапазона оценщик не создаёт фиктивную сумму.
- Компонент не вызывает Pipeline и не меняет его поведение.

### Ограничения RC2.4

- Нет расчёта ожидаемой выручки по количеству клиентов, конверсии, марже или истории продаж.
- Нет конвертации валют.
- Нет проверки источника, даты, достоверности или применимости диапазона к конкретной возможности.
- Нет агрегации нескольких источников.
- Нет интерпретации одиночной суммы как диапазона.
- Нет применения данных агентства из `RevenueIntelligenceContext`.
- Вывод нельзя трактовать как финансовый прогноз или обещание результата.

## Будущие расширения

Расширения должны сохранять изоляцию и объяснимость текущего слоя.

1. **Проверяемые источники и provenance**  
   Хранить ссылку на источник, время получения и идентификатор доказательства, из которого извлечён диапазон.

2. **Политика валидации evidence**  
   Добавить правила свежести, доверия к источнику и подтверждение соответствия суммы возможности.

3. **Валютные курсы**  
   Вводить конвертацию только через версионированный источник курса, с указанием даты, курса и метода.

4. **Агрегация диапазонов**  
   Объединять несколько доказательств только при явно определённой семантике: независимые эффекты, альтернативные сценарии или уточнения.

5. **Контекст агентства**  
   Использовать безопасные агрегированные показатели из контекста после появления согласованных, тестируемых правил и границ ответственности.

6. **Калиброванные прогнозы**  
   Возможны только как отдельный компонент с историческими данными, метриками качества, версионированием модели и явным отделением прогнозов от извлечённых фактов.

7. **Наблюдаемость**  
   Добавить метрики доли unknown-результатов, причин отказа, используемых валют и качества последующей верификации пользователем.
