# Мониторинг

## Endpoints

| Endpoint | Назначение | Успех |
|---|---|---|
| `/health` | Совместимый общий статус | `200` |
| `/health/live` | Liveness процесса | `200` |
| `/health/ready` | Готовность к рабочему трафику | `200`, иначе `503` |
| `/metrics` | Prometheus-совместимые HTTP-метрики | `200` |

Docker healthcheck backend использует `/health/ready`; frontend проверяет `/`.

## Readiness-проверки

`/health/ready` возвращает детальные статусы:

- `database` — запрос `SELECT 1`;
- `migrations` — текущая ревизия базы равна `alembic head`;
- `source_manager` — SourceManager доступен;
- `scheduler` — валидна конфигурация расписания;
- `metrics` — HTTP-метрики рендерятся;
- `feature_flags` — feature flags доступны для чтения.

При сбое хотя бы одной проверки endpoint возвращает `503` с диагностикой. При тех же условиях application lifespan завершает startup с понятной ошибкой.

## Рекомендуемые алерты

1. `/health/live` недоступен более 1 минуты — критический инцидент.
2. `/health/ready` возвращает `503` более 5 минут — блокировать новый трафик.
3. Ошибка `migrations` — немедленно проверить `migrate` и не выполнять ручной SQL.
4. Рост 5xx по `/metrics` — исследовать логи с `X-Request-ID`.
5. Ошибка `source_manager` — проверить конфигурацию источников без вывода секретов в логи.

## Логи

Backend пишет структурированные логи. Для корреляции запросов используется `X-Request-ID`, который принимается от клиента или генерируется middleware. Секретные поля маскируются до записи в лог.
