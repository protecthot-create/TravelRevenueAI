# План интеграции Revenue Intelligence

## Статус RC2

Интеграция не выполняется. Пакет создан и тестируется как изолированный слой.

## Предлагаемые этапы

### RC2.1 — контрактная стабилизация

- завершить архитектурные тесты;
- зафиксировать сериализацию моделей;
- сохранить отсутствие зависимостей от инфраструктуры.

### RC2.2 — адаптер входа

- определить отдельный application-level адаптер `Signal → RevenueIntelligenceInput`;
- не менять `Signal`, `raw_data`, `score` или `status`;
- покрыть адаптер интеграционными тестами.

### RC2.3 — правила без LLM

- реализовать детекторы и оценщики с детерминированными правилами;
- ввести проверяемые конфигурации порогов;
- добавить fixture-наборы и тесты ошибок.

### RC2.4 — persistence и представление

- отдельно согласовать модель хранения результатов;
- отдельно определить отображение результатов и связь с существующими карточками/брифингом;
- не менять существующие сервисы до совместимого контракта и migration-плана.

### RC2.5 — внешние/LLM-адаптеры

- ввести отдельные интерфейсы внешних источников;
- добавить таймауты, observability, redaction и feature flags;
- включать только после оценки качества и безопасности.

## Условия начала интеграции

1. Утверждён контракт результата.
2. Есть отдельный owner интеграционного адаптера.
3. Изменения Pipeline и существующих сервисов проходят отдельное ревью.
4. Есть rollback/feature-flag стратегия.
