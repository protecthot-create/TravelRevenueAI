## 1. Назначение модуля

Revenue Scoring Engine рассчитывает числовую оценку (score) для каждого нормализованного сигнала. Score используется для сравнения сигналов между собой и приоритизации.

Модуль отвечает на вопрос: «Насколько важен этот сигнал для денег агентства?»

Модуль не принимает решений о фильтрации — он только оценивает. Решение о том, показывать ли сигнал пользователю, принимает Filtering Engine.

---

## 2. Какие сигналы поступают на вход

На вход поступают нормализованные сигналы из Data Normalization. Каждый сигнал уже приведён к единому формату и содержит базовые поля.

### Типы входных сигналов

- **Возможность** — сигнал, указывающий на потенциальный заработок или рост выручки.
- **Риск** — сигнал, указывающий на потенциальную потерю денег.
- **Рыночный** — сигнал об изменении на рынке, которое может повлиять на деньги.
- **Операционный** — сигнал об эффективности внутренних процессов агентства.

### Источники входных сигналов

- внутренние источники (история продаж, маржа, данные по бронированиям);
- рыночные источники (цены, курсы валют, конкуренты);
- поведенческие источники (поисковые тренды, спрос);
- операционные источники (скорость обработки заявок, возвраты).

Подробнее: Rules `sources. md`.

## 3. Структура одного сигнала

Сигнал на входе в Revenue Scoring Engine содержит следующие поля:

```
signal_id          — уникальный идентификатор сигнала
signal_type        — тип: opportunity / risk / market / operational
source             — источник сигнала
timestamp          — время поступления сигнала
raw_data           — исходные данные сигнала

normalized_data:
  money_effect     — денежный эффект (число, может быть отрицательным)
  urgency          — срочность (в часах до дедлайна)
  probability      — вероятность реализации (0.0 – 1.0)
  controllability  — управляемость (0.0 – 1.0)
  deadline         — дедлайн (datetime)
  confidence       — уверенность в данных (0.0 – 1.0)

context:
  agency_size      — размер агентства: small / medium
  specialization    — специализация агентства
  season           — текущий сезон: peak / low / normal
```

Подробнее о структуре: Rules `revenue_score. md`, `scoring_rules. md`.

## 4. Какие характеристики оцениваются

Для каждого сигнала оцениваются четыре базовых характеристики.

### 4.1. Денежный потенциал (Money Potential)

Размер денежного эффекта сигнала в рублях.

| Диапазон | Оценка | Описание |
|----------|--------|----------|
| > 200 000 ₽ | 40 | Очень высокий |
| 100 000–200 000 ₽ | 30 | Высокий |
| 50 000–100 000 ₽ | 20 | Средний |
| 15 000–50 000 ₽ | 10 | Низкий |
| < 15 000 ₽ | 5 | Очень низкий |

Для рисков: отрицательный денежный эффект получает повышенную оценку.

### 4.2. Срочность (Urgency)

Время до наступления события или закрытия окна возможности.

| Дедлайн | Оценка | Описание |
|---------|--------|----------|
| < 24 часов | 25 | Критический |
| 24–48 часов | 20 | Очень срочный |
| 3–7 дней | 15 | Срочный |
| 1–2 недели | 10 | Умеренный |
| > 2 недель | 5 | Низкий |

### 4.3. Вероятность (Probability)

Насколько вероятен ожидаемый результат.

| Вероятность | Оценка | Описание |
|-------------|--------|----------|
| > 90% | 25 | Почти наверняка |
| 70–90% | 20 | Высокая |
| 50–70% | 15 | Средняя |
| 30–50% | 10 | Низкая |
| < 30% | 5 | Очень низкая |

### 4.4. Управляемость (Controllability)

Может ли агентство повлиять на результат.

| Фактор | Оценка | Описание |
|--------|--------|----------|
| Полный контроль | 10 | Агентство делает всё само |
| Частичный контроль | 7 | Зависит от партнёров |
| Ограниченный контроль | 4 | Можно влиять частично |
| Нет контроля | 1 | Внешний фактор |

Подробнее: Rules `scoring_rules. md`, `revenue_score. md`.

## 5. Какие факторы влияют на Revenue Score

Помимо базовых характеристик, на финальный score влияют модификаторы.

### 5.1. Модификатор для рисков

Риски получают +10% к финальному score. Это отражает приоритет рисков над возможностями при равной сумме.

### 5.2. Модификатор для повторяемости

Если действие можно повторять регулярно, score получает +5%. Это отражает долгосрочную ценность повторяемых действий.

### 5.3. Модификатор для контекста

Если сигнал соответствует специализации агентства, score получает +10%. Агентство, специализирующееся на Турции, получает больший score от сигналов по Турции.

### 5.4. Модификатор для сезона

Если сигнал актуален для текущего сезона, score получает +5%. Сезонные возможности и риски имеют больший приоритет в пиковый период.

### 5.5. Модификатор для размера агентства

Пороги денежного эффекта адаптируются под размер агентства:
- малый бизнес (1–3 сотрудника): порог снижается на 30%;
- средний бизнес (4–10 сотрудников): стандартные пороги.

Подробнее: Rules `scoring_rules. md`, `filtering_rules. md`.

## 6. Как рассчитывается итоговый Score

### 6.1. Базовая формула

```
Base Score = (Money × 0.35) + (Urgency × 0.30) + (Probability × 0.25) + (Controllability × 0.10)
```

Веса:
- Деньги: 35%
- Срочность: 30%
- Вероятность: 25%
- Управляемость: 10%

### 6.2. Применение модификаторов

```
Final Score = Base Score × (1 + Σ modifiers)
```

Модификаторы суммируются и применяются как мультипликативный фактор.

### 6.3. Пример расчёта

**Сигнал: Раннее бронирование Турция**

```
Деньги: 85 000 ₽ → 20
Срочность: 48 часов → 20
Вероятность: 72% → 20
Управляемость: полный контроль → 10

Base Score = (20×0.35) + (20×0.30) + (20×0.25) + (10×0.10) = 7 + 6 + 5 + 1 = 19
Модификатор повторяемости: +5% → 19 × 1.05 = 20

Финальный Score: 20
```

**Сигнал: Риск роста цен на авиабилеты**

```
Деньги: -60 000 ₽ → 25 (риск)
Срочность: 24 часа → 25
Вероятность: 80% → 20
Управляемость: частичный контроль → 7

Base Score = (25×0.35) + (25×0.30) + (20×0.25) + (7×0.10) = 8.75 + 7.5 + 5 + 0.7 = 22
Модификатор риска: +10% → 22 × 1.10 = 24

Финальный Score: 24
```

Подробнее: Rules `scoring_rules. md`.

## 7. Какие пороги определяют Opportunity, Neutral и Risk

### 7.1. Диапазоны Score

| Диапазон | Категория | Действие |
|----------|-----------|----------|
| 0–15 | Шум | Отклонить |
| 16–25 | Слабый | Низкий приоритет |
| 26–35 | Средний | Средний приоритет |
| 36–45 | Сильный | Высокий приоритет |
| 46–55 | Критический | Показать немедленно |

### 7.2. Уровни важности

| Уровень | Название | Когда показывать |
|---------|----------|-------------------|
| 1 | Критический | Немедленно, в любой момент |
| 2 | Высокий | В первую очередь в брифинге |
| 3 | Средний | В брифинге, но не в первую очередь |
| 4 | Низкий | Только по запросу |
| 5 | Игнорировать | Не показывать |

### 7.3. Матрица важности

| Денежный эффект | Срочность | Вероятность | Уровень |
|-----------------|-----------|-------------|---------|
| > 100 000 ₽ | < 24ч | любая | 1 |
| > 100 000 ₽ | > 24ч | > 50% | 2 |
| 50 000–100 000 ₽ | < 72ч | > 50% | 2 |
| 50 000–100 000 ₽ | > 72ч | любая | 3 |
| 15 000–50 000 ₽ | < 7 дней | > 50% | 3 |
| 15 000–50 000 ₽ | > 7 дней | любая | 4 |
| < 15 000 ₽ | любая | любая | 4–5 |

Подробнее: Rules `importance_rules. md`, `revenue_score. md`.

## 8. Что передаётся в Filtering Engine

Revenue Scoring Engine передаёт в Filtering Engine структурированный результат оценки.

### Выходные данные модуля

```
signal_id          — идентификатор сигнала
score              — финальный числовой score
priority_label     — метка приоритета: critical / high / medium / low / noise
confidence         — уверенность в оценке (0.0 – 1.0)
reason             — краткое объяснение расчёта
breakdown          — разбивка по компонентам:
  money_score      — оценка денежного потенциала
  urgency_score    — оценка срочности
  probability_score — оценка вероятности
  controllability_score — оценка управляемости
  modifiers_applied — применённые модификаторы
signals_passed     — флаг: прошёл ли сигнал порог для передачи
```

Подробнее: Rules `system_architecture. md`, `filtering_rules. md`.

## 9. Какие правила должны быть настраиваемыми

Следующие параметры должны быть настраиваемыми через конфигурацию:

```
WEIGHT_MONEY = 0.35
WEIGHT_URGENCY = 0.30
WEIGHT_PROBABILITY = 0.25
WEIGHT_CONTROLLABILITY = 0.10
```

```
MODIFIER_RISK = 0.10
MODIFIER_REPEATABLE = 0.05
MODIFIER_CONTEXT_MATCH = 0.10
MODIFIER_SEASON = 0.05
```

### 9.3. Пороги денежного эффекта

```
THRESHOLD_VERY_HIGH = 200000
THRESHOLD_HIGH = 100000
THRESHOLD_MEDIUM = 50000
THRESHOLD_LOW = 15000
```

### 9.4. Пороги для размера агентства

```
AGENCY_SIZE_SMALL_THRESHOLD = 3
```

```
SCORE_NOISE_MAX = 15

```

### 9.6. Пороги для сезонности

```

```
